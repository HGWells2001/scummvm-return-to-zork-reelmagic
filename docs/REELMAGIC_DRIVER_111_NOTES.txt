ReelMagic Release 1.11 compatibility notes
===========================================

Source generation
-----------------
The original ReelMagic driver package examined during compatibility research
identifies itself as ReelMagic Release 1.11, dated 1994-04-05. Its README states
that Return to Zork requires Release 1.11 or later and that the RTZ CD includes
Release 1.11.

No driver binary is included in this repository.

FMPDRV API observations
-----------------------
The DOS load module has a 0x200-byte MZ header. Its resident interrupt entry
contains the literal marker "FMPDriver". The command dispatcher contains 16
entries for commands 01h through 10h.

Dispatch targets observed in this Release 1.11 binary:

01 1811   02 182F   03 18A9   04 18BE
05 18EA   06 196F   07 1934   08 18FA
09 186F   0A 183F   0B 194B   0C 1986
0D 1991   0E 199A   0F 18CE   10 19A6

The parameter tables explicitly contain:

- 0208h user data
- 040Dh VGA alpha palette index
- 040Eh surface Z-order

for both SET and GET paths.

The status-query dispatcher maps 0204h, play state, to its own handler. This
independently supports the conclusion that MADERM's state wrapper is based on
the real driver play-state query rather than a game-local timer.

Combined MADERM + FMPDRV observations
-------------------------------------
The matching Return to Zork MADERM wrapper performs these operations:

- initializes 040Dh to parameter 0, making VGA palette index 0 the transparent/alpha index;
- sets ReelMagic magic key 0210h to 0x40044041;
- maps raw driver play state to MADE stopped/playing/paused values;
- resumes by querying 0208h and issuing Play with 0301h or 0304h;
- sets per-movie Z-order to 2, MPEG in front, or 4, MPEG behind.

Pause edge case
---------------
If an MPEG decoder is created while ScummVM is already globally paused, the
new decoder must itself receive `pauseVideo(true)` immediately. Freezing only
the MADE frame clock is insufficient because MPEG audio can otherwise advance
under the paused UI and resume out of sync.
